# 審査・品質チェック指示文

各段階の指示文を Claude Code に貼って使う。`【】` を埋める。
判定が「低」なら、次の段階に進まず計画や実装を直す。ダイスや縛りは設計の中身だけに効き、これらのチェックには効かない。

## 新規アプリ(流れ順)
| 段階 | ファイル | タイミング |
|---|---|---|
| 0 受け取り | 0_brief_intake.md | 詳細設計書・参考画像を受け取った最初(ダイス → 3つの質問 → アイコン用プロンプト → 再設計) |
| 1 企画時 | 1_planning.md | コードを書く前 |
| 1b 差別化 | 1b_growth.md | 企画時(段階1と一緒に) |
| 2 開発中 | 2_development.md | 主要機能ができた時。TestFlight もここで開始 |
| 2b 想定外 | 2b_edge_cases.md | 開発中(段階2と一緒に)。想定外のバグ・ユーザーで品質とコンテンツを広げる |
| Codex レビュー | codex_review.md | 区切りごと。Codex に渡す独立レビュー指示 |
| 3 提出前 | 3_submission.md | 申請の直前。通過後に申請キットを作る |

## ChatGPT / Codex に任せるレビュー
Claude の負荷を下げるため、レビューは `external/` の指示文で ChatGPT / Codex に任せる(企画・画面・文面)。詳細は `external/README.md`。
