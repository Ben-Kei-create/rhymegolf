# X(旧Twitter)での宣伝・TestFlight 募集プレイブック

既定のアカウント: **https://x.com/AIJAPANE**(開発者アカウント。公開アカウントなので、記載してよい)
他のアカウントを使う時は、オーナーが指示する。

## 役割分担
- **Claude(AI)**: 投稿文の下書き、ハッシュタグの案、返信文の案、スケジュール案を作る。`docs/marketing_posts.md` に保存する。
- **オーナー**: X への投稿・返信・画像の添付を行う。AI は X を操作できない。
- 有料広告(X 広告など)は、オーナーが指示した時だけ案を出す。普通の「宣伝」は、通常の投稿を指す。

## 時期ごとの投稿(優先順)
| 時期 | 目的 | 投稿の種類 | 雛形(`post_templates.md`) |
|---|---|---|---|
| 開発中(段階2) | TestFlight のテスターを集める | 募集 | A |
| 開発中 | 反応を取り、改善の根拠を作る | 開発ログ、画面のチラ見せ、2択の質問 | B |
| リリース前 | 期待を作る | 告知、事前予告 | C |
| リリース日 | 初週の初速を作る | ローンチ | D |
| リリース後 | 継続・口コミ | 使い方の小ネタ、アップデート、感謝と返信 | E |

## 書き方の型
1. **フック**(最初の1行): 誰の、どんな困りごと/驚きか。アプリ名から始めない。
2. **価値**: 何ができるか。1つに絞る(機能の羅列にしない)。
3. **証拠**: 実際の画面(スクリーンショット、短い動画)。実在する機能だけ。
4. **行動**: 一つだけ頼む(TestFlight リンクを開く、App Store で見る、感想をください)。
- 語り口は、そのアプリの **Voice mode**(人格)に合わせる。アカウント全体の一貫性は、ゆるく保つ。
- 文字数: X は日本語を2文字分として数える(目安: 日本語は 140 文字前後)。投稿前に X の画面でカウントを確認する。
- 画像・短い動画を添える。画像のテスト広告・デバッグ表示・個人情報を写さない。

## ハッシュタグ
- 1〜3個。多すぎない。本文の自然な位置か、末尾に置く。
- 固定の候補: `#個人開発` `#iOSアプリ` `#AppStore` `#SwiftUI` `#TestFlight`
- 状況別の候補: 募集 `#TestFlight` `#テスター募集` / 開発ログ `#個人開発` `#buildinpublic` / リリース `#iOSアプリ` `#リリースしました`
- ジャンル別: アプリの題材のタグを1つ(例: クイズなら `#クイズ`、学習なら `#学習`)。AI が、アプリごとに案を出す。
- ハッシュタグの人気度や効果は、AI は測れない。オーナーが X の検索で確認する。

## TestFlight 募集の要点
- 公開リンクを使うと、メールを集めずに募集できる(App Store Connect の TestFlight で作る。外部テストは Beta App Review が必要な場合がある)。
- 募集文に書く: 何のアプリか(一言)、テストしてほしい点(1〜2個)、期間(1〜2週間)、フィードバックの方法(返信 / フォーム)。
- 集まった意見は `docs/testflight_feedback.md` に記録し、反映した修正を返信で報告する(審査の質問4の材料にもなる)。
- テスターの個人情報(メール、名前)を、投稿や記録にそのまま書かない。

## 守ること
- 実装されていない機能、誇張、実在しない実績・レビューを書かない。
- 他社のブランド・商標・キャラクターを無断で使わない。
- 評価の水増し、レビューの依頼の強要をしない(規約違反)。
- 広告・プロモーションであることが分かる書き方にする(必要なら `#PR`)。
- 個人情報(姓名、メール、電話)を書かない。
- 反応が少なくても、投稿を消したり、過度に連投したりしない。

## 記録
- 投稿案と実際に投稿したものは、`docs/marketing_posts.md` に残す。
- 反応が良かった型・悪かった型は、アプリ完了後に `ExperiencePoints.md` の候補にする。
